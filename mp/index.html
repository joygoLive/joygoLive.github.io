A playlist with notes, served two ways.

A hand-curated catalogue of songs kept in one JSON file. Each entry carries the performer, lyricist, composer, a note on what the song is about, and its source. The same file drives an offline Android app and a streaming web app.

Premise

A playlist is a list of IDs. A catalogue is data.

A platform playlist holds video IDs and nothing else: no credits, no notes, no offline copy, and entries disappear when an upload is removed. The catalogue behind MyPlay started as a recovery of one such playlist and became a file with a schema, owned outside any platform.

The catalogue is a file, not a playlistOne JSON file is the source of truth. Per song: title, performer, lyricist, composer, theme note, source line, and video ID. Lists are keys in that file; adding a song is a data change, not a code change.
Notes are part of the songEach song has a short note on what it is about and a source line with year, writer, and chart or album. During playback the note is shown as a caption line and can be toggled off. Notes exist in Korean and English.
Two players, no forkThe offline app and the web app read the same file. Media differs by path: local files on the phone, YouTube embeds on the web. Nothing about the catalogue is duplicated between them.
Catalogue

What each entry carries

Three lists in one file. The fields below are what a player needs to show a song properly, and they are the same fields on both paths.

Three listsMy Play List, Apple Music, My K-Pop. Each list is a key in the file; each song is a numbered entry under it. Playback can be scoped to one list or all three.
Credits per songPerformer, lyricist, and composer as separate fields, so search hits on any of them. A cover and its original are distinguishable.
Display language follows the songA Korean song shows its Korean title and artist in the Korean UI; a pop song stays in English on both. The English UI uses English notes throughout. The rule is the song's language, not the screen's.
Search across both scriptsThe search index holds the original and localised title and artist together, so a query in either script matches regardless of the UI language.
Playback

Same catalogue, two players

The web app is a single HTML file with no dependencies. The Android app is a sideloaded APK built without Gradle. Both show the same title, credits, and note for a song; only the media source differs.

One player instanceThe web app creates exactly one YouTube player. Requests that arrive before it is ready are queued and played once, which removes the case where a failed first embed spawned a second player and two videos played at once.
Embed failures skipWhen an upload blocks embedding or is region- or age-restricted, the player advances to the next song. Shuffle covers one list or all three; playback speed runs from 1× to 2×; seeking is by 10-second steps.
Play log never blocks playbackEach play is logged as one row. The endpoint returns 200 unconditionally and the client ignores failures, so a logging outage cannot interrupt a song. Aggregates are computed at read time, not stored.
Pipeline

One file, two deployments

The catalogue is edited in one place and pushed to both players. A sync tool reports song count and content hash for the local file, the repository copy, and the copy on the phone, side by side, before anything is pushed.

Web pathCommit the file, push, and Cloudflare Pages deploys the static root. There is no build step: the web app is one HTML file that fetches the catalogue at load.
Phone pathThe file is pushed over adb into the app's private directory, and the app picks up the change without reinstalling. Media files are not part of the sync; the phone already holds them.
Song requestsAnyone can request a song from the web app with a title or a link, anonymously, rate-limited per day. Requests are stored, forwarded to a notification channel, and moved through received, approved, added, or rejected by the operator. If the server is unreachable the request stays in the browser with a mail fallback.

Limits

What this does not claim

MyPlay is a player over a curated file. Below is what it is not.

Not a music serviceNo rights are held and no audio is served. The web app plays YouTube uploads through the official embed player; availability, ads, and playback quality are YouTube's. A song whose upload disappears disappears from the web path with it.
One person's curationThe lists are a personal selection, not a chart or a recommendation. Notes are editorial: written per song, reviewed, and revised when found wrong. They describe what a song is about, not how good it is.
The offline app is not distributedIt runs on personal devices, sideloaded, with media that was exported from the owner's own account. It is not on a store and is not offered for install.
Not every song plays on the webEmbedding is the uploader's setting. Songs with embedding disabled, or restricted by region or age, are skipped on the web path and remain playable only in the offline app.
No accounts, no identityRequests are anonymous by design. The play log records the song, the time, and a hashed address for rate limiting; nothing identifies a person, and nothing is shared.
